# 我把 CCF 目录做成了一个论文门户

起因很简单：查论文的时候我总在几个工具之间来回跳——DBLP 查会议目录，Google Scholar 看被引，arXiv 下 PDF，还得自己记得 CCF 等级和截稿日期。这些信息明明都是公开的，为什么没有一个地方能按「CCF 等级 → 领域 → 年份」直接浏览全卷论文、带摘要、带被引、还能顺手收藏？

于是我花了两周，在自己的博客里做了一个 **CCF 论文门户**（导航栏的「CCF」入口）。这篇文章讲讲它能做什么、数据从哪来、以及踩过的坑。

## 它能做什么

**按 CCF 第七版官方目录浏览。** 我拿到了 2026 年 3 月发布的第七版目录的结构化数据（295 本期刊 + 387 个会议），把它们映射进 17 个领域分组——从体系结构（SC、ASPLOS、TPDS）到计算理论（STOC、FOCS、SODA），从网络与安全（SIGCOMM、CCS、S&P）到人机交互（CHI、UIST）。每个会议/期刊下面按年份展开全卷论文，标题、作者、摘要就地展开，被引数排序。

**搜索优先。** 首屏就是一个搜索框：输入标题或作者，先查本站快照和收藏，然后实时查 OpenAlex（被限流时自动降级到 Semantic Scholar）——不用先点开某个会议再搜索。

**每个来源都被验证过。** 接入一个会议/期刊之前，脚本会先确认 OpenAlex 里它近两年确实有收录（防张冠李戴），烤出来的快照会再从 Semantic Scholar 按 DOI 批量补 arXiv 链接、PDF 和缺失的摘要，最后从摘要里提取 GitHub 代码仓库链接。论文卡片上的「PDF / arXiv / Code / DOI」四个入口就是这么来的。

**收藏不只是收藏。** 可以标记想读 / 在读 / 已读三态，导出全部 BibTeX，一键把论文元数据送进站内写作编辑器开一篇笔记——笔记里的 `[@key]` 会被自动渲染成指向参考文献的上标。配置一个 Cloudflare Worker 之后，收藏还能跨设备同步。

**它自己会长大。** 一条 GitHub Actions 管线每周自动探测各会议/期刊的新一届论文（CVF、PMLR、ICLR、ACL Anthology、Crossref），烤成快照、补全摘要、重建索引、构建校验，然后自动提交部署。配额重置后首次运行会把 CCF 目录的剩余条目全部补齐。

## 数据从哪来，坑在哪

最难的不是写页面，是数据。这个门户现在同时使用四个数据源，各有各的脾气：

- **OpenAlex**：覆盖面最好的学术图谱 API，免费免密钥。但它对新一届会议的收录有几个月的滞后，Elsevier 期刊的摘要十有八九是空的，个别条目还混着 sci-hub 的死链（我在加载层做了消毒）。
- **Semantic Scholar**：补 OpenAlex 缺口的好备源，对 COLING、ICASSP 这类 OpenAlex 收录为零的会议反而很全。代价是未认证限流 1 秒 1 次请求，批量补全要有足够的耐心和退避。
- **官方 proceedings**：CVF（CVPR/ICCV/WACV）、PMLR（ICML/AISTATS/CoRL/COLT）、ICLR、ACL Anthology、JMLR、Crossref——这些都是最完整、最及时的一手数据，我把它们烤成静态快照直接随站点发布。
- **DBLP**：收录最快的索引，但现在有反爬验证。ECCV 2026 那次是让无头浏览器过了一遍验证才拿到的数据。

最大的坑其实是工程细节：CI 全新 checkout 没有 `.tmp-patch` 目录导致脚本秒崩、Shell 转义把补丁脚本搅成乱码、OpenAlex 按日配额把批量解析拖到每分钟一条、Semantic Scholar 对「全部 DOI 都不认识」的批量查询返回 400 而不是空数组……都是一次次红了的 CI 喂出来的。

## 和手工维护的学术主页比

学术圈的个人主页有个事实标准（比如 Jon Barron 的站点）：手工维护一份出版物列表，链接到 DBLP 和 Semantic Scholar。那个模式的优势是可控和精致，但每一篇都得自己录。

这个门户选择了另一条路：**数据全部来自权威 API 和官方 proceedings，站点只负责把「CCF 等级」这个中文计算机社区特有的坐标系叠加上去**——这件事 DBLP 和 Google Scholar 都不会帮你做。等级、排序、领域分组，全部以 2026 年 3 月发布的第七版官方目录为准。

## 接下来

- CCF 目录全量覆盖（管线已就绪，数据源配额恢复后在自动收尾）
- 快照年份的被引数周度刷新
- 更多官方 proceedings 源的自动探测

如果你也想给自己的博客加一个，整套数据管线就在仓库的 `scripts/` 目录里——从探测、烤制、补全到接线都是独立脚本，`npm run` 一条命令一个动作。
